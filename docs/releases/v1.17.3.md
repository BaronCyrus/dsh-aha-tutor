# v1.17.3：云端语音的字幕不再抢跑

这一版修正了使用云端语音时字幕和板书跑在声音前面的问题：现在每句话单独合成，一句话的声音响起时，它的字幕和板书一起出现。

- **字幕和声音对上**：以前云端语音把一步讲解合成一整段音频，插件按估算的每句时长来切换字幕。带数字、单位和公式的句子被估得太短，字幕和板书会抢在声音前面，用户反馈的视频里最多提前近 3 秒。现在每句话单独请求语音，字幕和板书在这句音频开始播放时切换。
- **按读法估算时长**：数字按中文读法计算（298 读作“二百九十八”），符号按读出来的字计算（≈ 读作“约等于”），DNA 这类缩写按字母逐个计算，标点处加上停顿。和两个系统语音的实际朗读对比，平均误差从 20% 降到约 6%。这个估算用来安排每句话里板书的节奏，以及不出声时整节课的节奏。
- **导出视频同样逐句合成**：用云端语音导出视频时，每句话也单独合成，字幕和板书从这句话的声音开始。
- **语音中途失败不再卡住字幕**：以前语音在一步中途失败，字幕会停在最后读到的那句，直到这一步结束。现在字幕跟着板书的进度往下走，不会退回已经读过的句子。
- **请求方式变化**：云端语音现在每句话发一次请求。同一步里一次只发一个请求，最多比正在读的句子提前两句，下一步的第一句也会提前取好。按字数计费的服务费用不变；这一版之前听过的课，第一次重听时会按句重新合成一遍。第一句以外的某句如果因为限流、服务器出错或断网失败，会再请求一次；服务返回 HTTP 429 限流时，会等一会儿再请求，最多两次。

验证：全部 402 项自动化测试、构建和发布包检查都已通过。以下内容在 DeepSeek Harness 0.2.2-rc.5 的独立 profile 中验证过，没有调用模型：

- 用 DeepSeek 云端语音（stella）播放一步带数字和公式的讲解（就是用户视频里的四句话）：第 2 到第 4 句的字幕都在这句音频开始播放后 1～2 毫秒内切换，句与句之间的空隙 7～8 毫秒；每段音频头尾各有约 0.2～0.3 秒静音，所以句间停顿约 0.5 秒，和用户视频里整段合成时的句间停顿（0.4～0.5 秒）相近；
- 顺着往下播放时，下一步的第一句已经提前取好，字幕和声音相差 5～6 毫秒；直接跳到某一步时，第一句要等语音返回（这次约 3 秒），这段时间里字幕先出现，这一点没有改；
- 用本机模拟的云端语音（macOS 系统语音真实合成，故意延迟 1.5 秒返回）复查了同样的结果，确认模拟服务收到的是一句一个请求、依次发出；播放中暂停 3 秒再继续，会接着原来的位置读完这一句；
- 导出一讲视频时，33 句话分别合成，每句的声音紧接着上一句排进视频；录制没有跑完，导出的成片没有实际看过；
- 火山引擎和 MiniMax 如果在返回内容里用错误码表示限流（而不是 HTTP 429），这一版的自动重试对它们不起作用；这一点还没有核实。

在 DSH 插件管理中更新至 **1.17.3**，然后重新打开 DSH 加载新版。
